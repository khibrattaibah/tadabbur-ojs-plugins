# سجل النزاهة البحثية — Research Integrity Log (OJS 3.5)

## للمحررين (سري)
- **فتح حالة** بأحد الأنواع الآتية: استلال، أو نشر مكرر، أو نزاع تأليف، أو تلفيق بيانات، أو سوء سلوك محكّم، أو تضارب مصالح غير مُفصح عنه، أو تلاعب بالاستشهادات، أو اشتباه مصنع بحوث، أو مخالفة أخلاقية، أو غير ذلك.
- **مصدر البلاغ:** قارئ، أو محكّم، أو محرر، أو مؤلف، أو جهة انتماء، أو فحص آلي، أو مجهول. ويمكن ربط الحالة ببحث.
- **خطوات COPE الموصى بها** لكل نوع، تُعلَّم عند إنجازها، مع رابط إلى مسارات COPE الرسمية.
- **خط زمني موثّق:** مراسلة المؤلف، والردود، ومراسلة الجهة، والأدلة، والقرارات. ويُسجَّل فيه آليًا كل تغيير في الوضع أو النتيجة.
- **الوضع:** مفتوحة، أو قيد التحقيق، أو بانتظار الرد، أو أُحيلت، أو مغلقة.
- **النتيجة:** لا إجراء، أو توجيه، أو تصحيح، أو تعبير عن قلق، أو سحب، أو رفض، أو إحالة.
- لا يطّلع على السجل إلا مدير المجلة ومحررو الأقسام. ولا تُحذف الحالات.

## للعامة
- **إشعار عام** مرتبط بالبحث، من أحد الأنواع: تصحيح، أو تعبير عن قلق، أو سحب، أو إزالة. نصه بالعربية والإنجليزية، ومعه DOI اختياري.
- يظهر **شريطًا بارزًا أعلى صفحة البحث** بلون بحسب نوعه، وقسمًا كاملًا أسفلها.
- **صفحة عامة:** `/integrity/notices` تجمع إشعارات التصحيح والسحب، ويمكن إضافتها إلى قائمة الموقع.
- وفق COPE لا يُحذف البحث المسحوب، بل يبقى متاحًا موسومًا بوضوح.

## ما لا تفعله
لا تودِع الإشعار في Crossref (Crossmark) آليًا. إن كان للمجلة اشتراك Crossmark فيُودَع الإشعار بـ DOI مستقل يدويًا، ثم يُكتب في حقل DOI للإشعار.

## البيانات
ثلاثة جداول: `integrity_cases` و`integrity_case_events` و`integrity_notices`. لا تُحذف عند الترقية ولا عند الإزالة.
